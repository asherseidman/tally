# CLAUDE.md: source of truth

(The product is called **Tally**; the repo, data folder and code names keep "todo-planner"/"planner". See "Tally rename and redesign".)

## Goal
Standalone personal to-do + planner for a college student. Electron desktop app with its own SQLite DB. NOT built on TickTick. Calls NO LLM and has NO LLM API keys; Claude produces JSON import files separately. Only external service: Google Calendar (Phase 3).

## How we work
- One phase at a time. At the end of each: run tests, update this file and README.md, commit, STOP and summarize. Do not start the next phase until the user says "continue".
- At the start of each phase, re-plan briefly and flag conflicts with earlier decisions.
- Never build later-phase features early (schema columns only).
- Tests for pure logic are written before implementation. Commit after each working milestone.
- Don't rely on memory for third-party APIs (Google OAuth, Calendar, Electron security, native rebuilds): check current docs.
- Provide demo data in a separate DB (`npm run seed` / `npm run demo`).
- Trial gate: SKIPPED by the user's choice (Phase 2 accepted without the trial week). If friction shows up later, fix the design then.

## Stack
Node + TypeScript (ESM, tsx), better-sqlite3 (behind `Db` interface in `src/db/index.ts`), zod 4, luxon, vitest. Phase 5: Electron + React + Vite.

## Conventions
- No hardcoded term/year/semester anywhere in logic. Terms are data (fixtures/samples may name them).
- Timestamps stored as UTC ISO strings; IANA timezone setting (default America/Detroit); default due time 23:59 (`time_assumed=1` when a date had no time).
- All "now" logic uses the injectable `Clock` (`src/clock.ts`).
- DB access only through `Db`; migrations in `src/db/schema.ts` via `PRAGMA user_version`.
- Import identity = `import_key` (immutable); never match on title/date.

## Layout
`src/db` (schema, Db, repo) · `src/import` (schema, importKey, diff, apply, review) · `src/schedule` (workingHours, availability, plan, service, settings, format, calendar iface, fakeCalendar, googleCalendar, auth, secretStore) · `src/core` (tasks, lists, terms, recurrence, naturalDate, backup, export, timer, learning, grouping, doctor, ctx) · `src/cli` (main = all Phase 2 commands, aliases, import, seed, demo, show, context, args, format) · `src/time.ts` · `src/clock.ts` · `src/paths.ts` · `docs/IMPORT_FORMAT.md` · `samples/` (fake, committed) · `imports/` (real, gitignored) · `scripts/verify-native.ts`.

- Existing term matched by name (case-insensitive); file dates for an existing term are ignored with a warning.

### Phase 2 decisions
- Core modules take a `Ctx` ({db, clock, tz, defaultTime}); the CLI is a thin layer (`src/cli/main.ts`). Phase 5 IPC should call `src/core`.
- Commands: `npm run plan -- <cmd>` (add/edit/done/undone/rm/undo/mv/show/ls/search/list/term/backup/backups/export/restore/timer/multipliers/config); aliases `npm run timer|backup|export|restore|multipliers`. `--demo` selects demo DB. Multi-word option values need no quotes (`--due fri 5pm`).
- Natural dates: chrono-node (forwardDate). It only knows UTC offsets, not IANA zones, so we pass local wall-clock "now" as if UTC and rebuild with luxon in the configured tz (DST-correct). Date with no stated time => default due time, `time_assumed=1`. Whole input must parse.
- Recurrence rule stored as JSON `{freq, interval, days?}`; next occurrence keeps LOCAL wall time (DST-safe) and skips occurrences already in the past. Completing creates the next as a new manual task; un-completing soft-deletes that spawned task (matched by created_at == completed_at). Repeating requires a due date.
- Scope: default = current term + term-less tasks. `--term X` = X + term-less. `--all-terms` = everything incl. archived. Archived terms are hidden from default views/search; `term use` refuses archived terms. `terms.is_current` is the single source of truth for the current term (no duplicate setting). Tasks with a course attach to the current term; tasks without course are term-less unless `--term` or a term-bound list says otherwise.
- `ls` hides done tasks by default (`--done`, `--all`, `--status`). `search` covers all statuses. Text search is LIKE over title/notes/course with wildcards escaped.
- Soft delete = `deleted_at`; `undo [id]` restores the latest/given. `list rm` deletes only the list; its tasks are kept without a list.
- Backups: SQLite online backup API into a temp file, integrity-checked, then renamed into place (a bad backup never looks good; failure is loud). Names `planner-YYYYMMDD-HHMMSS.db` in UTC. Auto-backup runs once per local day on any CLI command (default folder `<appdata>/backups`, `backups-demo` for demo; setting `backup_folder` overrides), keeps newest 14, ignores other files. `restore` verifies the backup, takes a `pre-restore-*.db` safety backup, asks you to type "restore" (or `--yes`), swaps the file. `import` does not trigger auto-backup (only `plan` commands do).
- Export: JSON (all tables, including archived terms and deleted tasks) + .ics (one 15-minute VEVENT per dated, non-deleted task, UTC). Default dir `<appdata>/exports`.
- Timer: `time_sessions` row per run; `actual_minutes` = sum of finished sessions (rounded minutes); unfinished sessions are never counted. Starting marks the task in_progress.
- Learning: per type, sum(actual)/sum(estimated) across ALL terms (archived included) for done, non-deleted tasks with manual/imported estimates only (learned estimates excluded to avoid compounding). Applied only with >= 3 samples. `add --est` prints a hint rather than silently changing your estimate; `estimate_source='learned'` is reserved for when the scheduler (Phase 3) applies it.
- Phase 3 caveat to remember: scheduler must apply `applyMultiplier` itself and respect `scopeClause` (current term + term-less, archived excluded).

### Phase 2 flagged choices (accepted by the user)
- **Multipliers are hint-only.** `add --est` prints "plan for ~N min" once a type has >= 3 samples; it never silently changes the user's estimate. `estimate_source='learned'` is reserved for the Phase 3 scheduler.
- **`--term X` shows X plus term-less tasks** (only the term part of the default scope is swapped). `--all-terms` is everything including archived.
- **`ls` hides done tasks** by default (`--done`, `--all`, `--status` to see them). `search` covers all statuses.
- **Repeating tasks need a due date** (`--repeat` without `--due` is an error; clearing the due date of a repeating task is refused).
- **Learned estimates are excluded from learning**: only manual/imported estimates feed the multipliers, so a multiplier is never learned from an already-multiplied estimate.
- **Phase 5 TODO (packaging) [DONE, see "Packaged macOS build"]:** `scripts/verify-native.ts` hardcodes the macOS Electron binary path (`Electron.app/Contents/MacOS/Electron`) and shells out to `electron-rebuild`. Phase 5 needs a proper rebuild step for packaging (`electron-rebuild` / `electron-builder install-app-deps`, native modules unpacked from asar, then `npm rebuild better-sqlite3` to return to the Node ABI for tests) and a cross-platform check script.

### Post-Phase-2 polish (small, no new features)
- **Import backs up too.** `import` runs the daily backup on start (like `plan` commands) and ALWAYS takes another verified backup right after an approved import is written (even if today already has one), then prunes to 14. A failed post-import backup is loud but does not undo the import. Not taken for `--dry-run`/quit.
- **Backup file hardening:** names have one-second resolution, so a same-second backup bumps its stamp instead of overwriting; backups are converted to a rollback journal (`makeSelfContained`) so they are single files with no `-wal/-shm` litter. Default backup folder now sits next to the database file (so `PLANNER_DB` overrides stay self-contained); explicit `backup_folder` setting still wins.
- **Aliases:** `a`=add, `d`=done, `l`=ls, `s`=search (`src/cli/aliases.ts`); full names unchanged.
- **`ls` is a daily view by default:** OVERDUE / TODAY / UPCOMING / NO DUE DATE (/ DONE with `--all`), overdue first. Overdue = due before now; today = rest of the LOCAL day; sorted by due date inside groups. `--by course|list` or `--deleted` gives the old flat/grouped-by-field output; all filters still apply.
- **`doctor`:** pass/warn/fail for database integrity, backup folder (must be explicitly set, writable; warns if on the same disk and not recognizably cloud-synced; cloud detection is a path heuristic and cannot prove sync works), last backup (fail if none or corrupt, warn if > 36h old), current term, timezone. Exit code 1 on any fail; warnings don't fail.

- **Working hours** (JSON in settings `working_hours`; per-term override `working_hours.term.<termId>`; per-date overrides in `schedule_overrides`, managed by `away add|rm|ls`). Validated with readable errors. Built-in default (9 AM-9 PM daily, no class rule) is used if nothing is saved. Sample/proposed routine: `samples/working-hours.json`.
- **Class rule (revised 2026-11-08):** `start: "after_first_class"` (renamed from `after_last_class`; saved settings are migrated automatically on load, including per-term and per-date overrides) = end of the FIRST class of the day; gaps between later classes are usable. First class = earliest-starting qualifying busy block on the chosen `class_calendars`. A busy block is NOT a class if it is all-day (>12h), shorter than `min_class_minutes` (45), lies entirely inside one of that day's fixed unavailable windows (the Tue/Thu gym, which also shows as busy on the class calendar), or starts at/after `class_cutoff` (18:00, e.g. an evening exam). Ignored blocks still count as busy time. No class that day => `default_start`. Free/busy has no titles, so "class" is inferred; `calendar classes [--days N]` prints the first class per day and every ignored block with its reason. Scheduling is refused with a clear message if the rule is used and no class calendars are set.
- **Assumptions the user did not specify (change in the JSON):** Saturday start = `default_start` 09:00; weekdays with no class start at 09:00; Saturday ends 20:00 (the stricter of "8:30 PM Thu/Fri/Sat" and "nothing after 8 PM Saturday"); buffer applies between planner blocks only (not around calendar events).
- **Planner:** tasks sorted by due time, then higher grade weight first (so heavier tasks get the later slot on ties). Each is placed as late as possible, finishing `deadline_slack_minutes` (120) before due and within working time, never before now (rounded up to 5 min), 5-minute grid, buffer between any two blocks. Short tasks are padded to the minimum block; long ones are split evenly (<= max). It prefers one whole block earlier over splitting into smaller pieces later. Work that does not fit is reported (`DOES NOT FIT`, partial or none), never dropped. Learned multiplier is applied in memory only; tracked time (`actual_minutes`) is subtracted. Skipped with a reason: no due date, no estimate, overdue, attendance type, estimate used up. Scope = current term + term-less tasks, archived excluded. Dependencies are ignored until Phase 4.
- **Apply/replan:** apply deletes this app's FUTURE blocks (start >= now) and rewrites the plan; past blocks stay as history. `replan --apply` also removes MISSED blocks (past, task still open) and reports what moved (missed/shifted/removed). Already-deleted events (404/410) count as success.
- **Exam windows (user-requested):** an open exam-type task with a real (non-assumed) time is a fixed busy window from that time for `exam_duration_minutes` (default 120, 0 = off) plus the buffer after it, so no work is placed during or right after. Applies even if the exam has no estimate; ignored if the time was only assumed, or the exam is done/deleted. Caveat: a TAKE-HOME exam with a real due time (e.g. MIDEAST 207 Final Exam, due Dec 18 5 PM) also gets a 2h window at its due time; set its type to `project` or give it an assumed time if that is unwanted. Shown in the plan as `EXAM h:mm-h:mm (blocked)`.
- **Approved working hours saved to the real DB** (2026-11-08) exactly as `samples/working-hours.json` (+ default `exam_duration_minutes: 120`): Sat ends 8 PM, Sun starts 1 PM, weekend gym 11-1.
- **All-day busy blocks:** `ignore_busy_at_least_hours` (default 20, 0 = off) ignores busy blocks that long (all-day events) instead of letting them blank a whole day; the plan lists what it ignored. Same threshold as the `calendar busy` warning flag. A calendar can also be excluded entirely with `config set busy_calendars <ids>`. (Separately, blocks over 12h never count as "a class".)
- **`calendar busy [--days N]`:** read-only list of the busy blocks the scheduler sees per calendar, flagging 20h+ blocks. First real Google call (freeBusy) verified 2026-11-08; the class calendar is read free/busy only. Personal and Family calendars are empty this week.
- **Known limitation:** because titles are unavailable, a long busy block on the class calendar (e.g. Tue 11:30 AM-2:30 PM) is taken as one class; a non-class block of 45+ minutes before 6 PM, other than a gym window, would be mistaken for a class. Options if that bites: lower `class_cutoff`, raise `min_class_minutes`, or request event-read scope to filter by title.
- **Planner rules added 2026-11-08 (all configurable in working hours; 0 turns off where noted):** (1) `min_lead_minutes` 30: nothing sooner than 30 min from now. (2) Tasks with `long_task_minutes` (60) or more minutes to schedule never get a block under `long_task_min_block_minutes` (30), so they are split into fewer, longer pieces or reported partial. (3) Tasks with `spread_threshold_minutes` (240) or more are spread over days: at most `spread_daily_max_minutes` (120) of that task per local day, and the last block ends at least `spread_days_before_deadline` (1) day before the deadline (the stricter of that and the 2h slack). Applies to the minutes still to schedule (after the learned multiplier and tracked time). Consequence: a big task with few usable days before a deadline is reported under DOES NOT FIT rather than crammed in.
- **Exam prep (user, 2026-11-08):** exam-type tasks big enough to be spread (240+ min) use their own numbers instead of the general spreading rule: last block may end `exam_prep_end_before_minutes` (120) before the exam starts, and up to `exam_prep_daily_max_minutes` (180) per day. Exams under 240 min are planned like any other task (2h slack). EECS 183 Exam 2 keeps its 360-minute estimate; MATH 214 Midterm Exam 2 now has 180 min so prep is scheduled before it (it keeps its 2h blocked window).
- **Placement detail:** every chunk of a task searches for the latest free slot before the deadline (it no longer has to sit before the previous chunk), so a spread task can use spare capacity on a later day; non-overlap is guaranteed by consuming windows.
- **Labs are not scheduled:** the lab tasks (e.g. DEMO 101 Lab 8/9/10) had their estimates cleared (`edit <id> --est none`; also clears estimate_source) and a note "Done during lab; not scheduled." They appear under NOT SCHEDULED with reason "no estimate". To keep this true: **re-imports never change estimates on existing tasks** (`estimated_minutes` is excluded from re-import diffs; a NEW task still takes the file's estimate as its starting value). Estimates come from the app.
- **Import backup fix:** the after-import backup is skipped when the import wrote nothing.
- **API facts checked in Google docs:** `events.insert`/`events.delete`/`calendars.insert` accept `calendar.app.created`; `freebusy.query` accepts `calendar.freebusy`; `calendarList.list` accepts `calendar.calendarlist.readonly`; freebusy max 50 calendars per request (we chunk). The `freeBusy` and `calendars` request URLs were not shown on the pages I read; the first real call confirms them.

### Availability, early placement, sizes (2026-11-10)
- **Availability windows are the source of truth for free time.** Table `availability_windows` (schema v2): `date` (YYYY-MM-DD) XOR `weekday` (1=Mon..7=Sun), `start`/`end` local HH:mm (end may be `24:00`), `kind` free|blocked. A weekly template (weekday rows) plus per-date rows. **If a date has ANY per-date row, those rows fully replace the template for that date.** Within the chosen set, free windows merge (overlapping/touching join) and blocked windows are subtracted (blocked wins). Times are local wall-clock and converted per date with luxon, so DST days are 23/25 hours long and 09:00 stays 09:00. Code: `src/schedule/availabilityWindows.ts` (pure resolution + DB ops: `setWindow`, `clearDate`, `copyWeek`).
- **First per-date edit copies the template onto that date** (user did not specify; flagged). Without it, "block 4-6 PM on Nov 9" would delete the rest of that day because per-date rows replace the template. `set` is newest-wins: it carves the opposite kind out of overlaps and merges same-kind overlaps.
- **Scheduler input = free windows minus busy calendar time** (all non-Planner calendars, class calendars included, plus exam windows) **minus nothing else.** Planner Blocks' own future events are NOT treated as busy: `apply` deletes and rewrites them, so a dry run equals an apply (unchanged Phase 3 behaviour; the user's "minus Planner Blocks events it manages" is satisfied by that replace semantics).
- **The `working_hours` JSON is now only seed input** for `availability seed [--weeks N] [--replace]`: it applies the old rules (`after_first_class` using the REAL class calendar, end times, gym windows, per-date `schedule_overrides`) to each of the next N weeks (default 4, starting today) and writes dated windows, plus a weekly template (per weekday, the pattern seen on most non-overridden days; used beyond the seeded weeks). Whole-day-unavailable overrides become a blocked 00:00-24:00 row. Seed refuses to overwrite existing windows without `--replace`. Class detection (`classifyDay`, `calendar classes`) now only serves the seed and that diagnostic.
- **Numeric knobs are plain settings** (`config set min_block_minutes 15`, etc.); each falls back to the saved `working_hours` JSON value, then the default. Keys: min_block_minutes, max_block_minutes, buffer_minutes, deadline_slack_minutes, min_lead_minutes, long_task_*, spread_*, exam_prep_*, exam_duration_minutes, ignore_busy_at_least_hours, plus the new ones below. `--hours` preview and `class_calendars required` errors are gone. `away add/rm/ls` are now shortcuts over availability (all-day or window blocked / clear date / list dated days).
- **Early placement (default) vs late.** `placement_style` = early | late. Late is the Phase 3 behaviour, pinned by the original tests (which now run through seeded availability with `placement_style late`). Early: a task becomes eligible `lead` days before its due DATE: `lead = early_lead_days` (3), or for big tasks (>= `spread_threshold_minutes`) `max(early_lead_days, ceil(minutes/120)+2)`. Blocks go in the earliest free slots from max(eligible start, now+lead time, `available_from`) and must end `finish_before_deadline_minutes` (240) before the deadline (exam prep keeps `exam_prep_end_before_minutes`, 120). Spread rules still cap a big task per day (2h; exam prep 3h). **Flagged choices:** (1) early mode drops the extra 1-day margin for 240+ min tasks (the 4h finish-before replaces it); late mode keeps it. (2) `max_daily_work_minutes` (300) is a SOFT cap across all tasks: it is exceeded only if the work would not otherwise fit, and those blocks are flagged "over the daily work cap" in the plan. Late mode has no daily cap. (3) `available_from` is also a floor in late mode.
- **Task fields (schema v2):** `size_amount`, `size_unit` (pages|video_minutes|problems|items), `available_from` (local date), `optional` (0/1), and `estimate_source` may now be `size` (the CHECK forced a table rebuild; done by migration v2 with foreign keys off and a `foreign_key_check` before commit).
- **Migrations take a verified backup first.** `openContext` calls `backupBeforeMigration` when the file's `user_version` is behind: online backup to `pre-migration-vA-to-vB-<stamp>.db` in the configured backup folder, integrity-checked, and the migration refuses to run if that fails. (Earlier, migrations ran inside `openDb` with no backup.)
- **Estimate order: manual (or imported) > size-based > none.** A manual estimate is never replaced silently (`edit <id> --size N unit` keeps it and prints the size-based number; `--est-from-size` switches; `estimates [--apply]` lists/switches all differences). `--est none` on a sized task falls back to size. Size-based = `amount x rate`; rates are rules `{unit, minutes_per_unit, course?, title_match?}`, user rules (`config set size_rates @file.json`) before defaults: WeBWorK problems 6 (title match), MATH 214 problems 15, pages 3, video_minutes 1.25, items 30. WeBWorK and written homework share the unit `problems`, which is why rules can match on title. A rate learns from DONE tasks with size + tracked time once a rule has >= 3 samples (actual min / amount, per rule); the per-type multiplier is NEVER applied to size-based estimates and never learns from them (`estimate_source` size is excluded). `show` prints the formula; `ls --needs-size` lists size-unit tasks with no amount (they are "NOT SCHEDULED: size unknown"). Optional tasks are skipped unless `include_optional_tasks` is true.
- **Import format** gained optional `size {amount, unit}` (amount may be null for "length unknown"), `available_from` (YYYY-MM-DD), `optional` (bool). They take part in re-import diffs and local-edit protection like other fields. Estimates still never come from a re-import.

### Phase 4 decisions (2026-11-11)
- **Dependencies** (`src/core/dependencies.ts`; table `dependencies(task_id, blocked_by_task_id)`): `dep add <task> <blocked-by>`, `dep rm`, `dep ls [task]`. Cycles (direct or through other tasks) are refused with the two task names. "Blocked" is derived, not stored: a task is blocked while any blocker is open (not done, not deleted), so completing a blocker releases its dependents automatically and undoing the completion blocks them again. The scheduler skips blocked tasks (listed under NOT SCHEDULED: "blocked by #N ..."). `show` lists blockers, dependents, parent and steps.
- **Plan import** (see docs/IMPORT_FORMAT.md): top-level `plans: [{parent:{course,title}, steps:[{title, estimated_minutes, due_date?, depends_on?: [step index]}]}]`. Steps become tasks (type `other`, `estimate_source` imported, `parent_task_id` = parent, parent's term and course), keyed `makeImportKey(term, course, "<parent title> :: <step title>")`. `depends_on` (as sorted import keys) is an import-diff field, so revised plans update dependencies and local rewiring is conflict-protected. Step-to-step links are rewritten to match the file; links to tasks outside the plan are never touched; a link that would loop with existing dependencies aborts the whole import. A plan-only file compares only with the steps of its parents (other tasks of the course are not "missing"). **Flagged choices:** (1) a step without a due date copies the parent's due date (and assumed-time flag) at import time, because undated tasks cannot be scheduled; (2) a parent with open steps is NOT scheduled itself (its work lives in the steps) and says so; (3) steps default to type `other`.
- **Views** (`src/core/views.ts`, one query layer; `npm run views [--term T] [--all-terms]`): Due Soon = open tasks due within `views_due_soon_hours` (72) plus overdue ones, soonest first; Quick Wins = remaining estimate (estimate or size-based, minus logged) of 1..`views_quick_win_minutes` (20) minutes, unblocked, not deadline-only, shortest first; Blocked = tasks with open blockers and what blocks them. Every item has a one-line reason. Scoped to the current term plus term-less tasks. Remaining effort uses the same estimate order as the scheduler.
- **High Grade Impact formula (approved 2026-11-11):** `score = weight% x urgency x effort_factor`, with `urgency = 1 / (1 + daysLeft / impact_urgency_days)` (due now = 1, in 7 days = 0.5) and `effort_factor = 1 / (1 + remainingHours / impact_effort_hours)` (4 hours of work halves it). `remainingHours` = estimate (manual or size-based) minus logged time; a task with no estimate is assumed `impact_default_minutes` and the reason says so. Candidates: open, graded (weight > 0), unblocked, with a due date that has NOT passed (overdue tasks are excluded here and stay in Due Soon). Top `impact_limit` by score. Constants are settings (`config set`): `impact_urgency_days` 7, `impact_effort_hours` 4, `impact_default_minutes` 60, `impact_limit` 10 (plus `views_due_soon_hours` 72, `views_quick_win_minutes` 20). Every item shows a reason like "worth 15%, due in 22 hours, ~5 hours of work". Code: `impactScore` and `computeViews` in `src/core/views.ts`.
- **`deadline_only` is now part of the import format** (`"deadline_only": true`): validated as a boolean (default false), stored, diffed like other fields (local choices protected). Nothing else about the format changed.
- **Tentative projections (2026-11-11):** a blocked task that would otherwise be schedulable is projected in the dry run as if each blocker finishes at the END of its own planned blocks (real or, for chains, tentative), using only the time the real plan leaves free (layer by layer in dependency order). Shown under "TENTATIVE (waiting on #N ...)", with "makes its deadline" or "WOULD NOT FIT (tentative)"; tentative problems also appear under DOES NOT FIT labeled "(tentative)". **Tentative blocks are never written to Google** (`applyPlan` only reads `report.blocks`) and are not limited by `--days`. A blocked task whose blocker has no planned time (no estimate, optional, overdue...) stays under NOT SCHEDULED, saying it cannot be projected. In late placement a blocker sits at its deadline, so dependents usually "would not fit"; the projection is meaningful with early placement (the default).
- **Planner fix (2026-11-11):** when a free stretch can hold a usable block but not the whole remainder, early placement now uses it for what fits (padding a tiny remainder to the minimum block, or reporting the true remainder) instead of leaving it empty. Found because Exam 2 left a 45-minute Wed 5:15-6:00 PM stretch unused.

### Rates screen (2026-11-13)
- **New top-level tab "Rates"** (`renderer/src/screens/Rates.tsx`, API `src/app/ratesApi.ts`, logic `src/core/rateGroups.ts`). No schema change (still v8): everything is settings, so there is nothing to migrate. Settings added: `rate_groups` (overrides: `names` group key -> name, `merges` group key -> group key, `moves` task id -> group key), `rate_defaults` (the built-in rate list, replaced wholesale once edited, order kept), `points_min_minutes`, `rate_multiplier_off` (group keys), `rate_multiplier_reset` (group key -> ISO time). Existing `size_rates` is still the user's rule list (so `rates set` from the CLI and the screen are the same data).
- **Grouping:** key = lowercased course + `|` + `stemOf(title)`. The stem drops "Lecture 22", "lectures 23 and 24", chapters, weeks, parts, units, modules, sections, sessions, dates (ISO, m/d, "Nov 12"), parenthesized segments that contain digits, ordinals (2nd, third), "#4" and any remaining numbers or ranges; empty -> the title minus digits, else "(untitled)". Every non-deleted task of every term (open and done) is in a group. Merges/moves/renames are keyed by group key and task id, so a task imported later with the same stem lands where the user put it. A saved rule belongs to the group holding most tasks its course + title text catches; a rule with no title text or matching no task is its own card ("All titles", “text”).
- **Group controls:** unit, minutes per unit (decimals), title-contains text with a live match preview (tasks in the same course; others flagged), live example (same rounding and points minimum as the estimates), Save rate (replaces that group's rule for that unit, else adds a new first rule), Reset to default (removes the group's rules), rate in use with its source (Your rate / Built-in default / Learned; Learned = the existing per-rule calibration from 3+ finished timed tasks) and rule number, actual rate (needs 3 finished tasks with size and tracked time; "Use actual rate" only fills the field), open total estimated minutes and count without an estimate, and per-task "no size set" flags. **Apply to these tasks** (`previewApply`/`applyToTasks`): open tasks with a size and a rate whose SAVED estimate is none or a stale size-based one; manual estimates only with an explicit tick; preview writes nothing; the API refuses without `confirm`, refuses a stale list (fingerprint of the rows), and the UI lists before/after for every task (and says more than 3 need a read-through). Live estimates already follow rate changes (effective estimates are computed from the rates each time); Apply writes the SAVED values.
- **Rule order:** unchanged (user rules, newest first, then the built-in list; first match wins; most specific first by construction). The Rates screen shows the whole order, yours then built-in; the task detail has a "Why this estimate" line (`TaskDto.estimateWhy`, `explainEstimate`): which rule number, yours or built-in, and the learned replacement if any. The 5-minute points minimum travels on the rule list (`RateList.pointsMin`) so no signature changed.
- **Learning per group (`buildLearning` in `src/core/learning.ts`):** the planner's multiplier is now: the task's group (course + stem + unit) when it has >= 3 finished timed tasks (manual/imported estimates only, as before), else the task type, else none; size-based estimates never get one (unchanged). A group with its switch off gets NO multiplier at all (it does not fall back to the type); Reset ignores tasks completed before the reset time. Shown per group on the Rates screen with the switch and Reset. FLAGGED choices: switch off means none, not "type only"; the CLI's `add --est` hint and `multipliers` table still use the per-type numbers.
